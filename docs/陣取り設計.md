# Ironfield 陣取り 設計書（たたき台）

作成: 2026-10-23（Ironfield #2）。ユーザーの依頼「Factorio の陣取り合戦系で、コツコツさが大事なゲームにしてほしい。課金などで差がつかないように」。
この設計書は数字も含めてたたき台です。遊んでみて直す前提です。

## 1. ひとことで言うと

自分の工場で「旗」を作り、旗を使って日本地図のマスを自分の都道府県のものにする、都道府県対抗の陣取りゲームです。
1日に使える旗の数に上限があるので、長時間遊んだ人よりも、毎日少しずつ続けた人が強くなります。お金で買える有利なものはありません。

## 2. 守る約束（設計の柱）

1. コツコツ続けた人が一番強くなるように、1日に陣取りに使える旗の数に上限を設ける。上限に届けば、それ以上遊んでも陣取りでは差がつかない。
2. お金で差がつかないように、ゲームを有利にするものは売らない。課金を入れるとしても、見た目だけ（工場の色、旗の模様）か寄付だけにする。
3. 旗は本物の工場づくりで作る。ベルトを引き、機械を並べ、生産の流れを組み立てるという、今の Ironfield の楽しさをそのまま使う。
4. 人数の多い県が有利になりすぎないように、人が多い県ほど1人の旗の力を小さくする（陣とりバトルと同じ考え方）。陣とりバトルは、2026年10月に X で流行った、都道府県ごとに日本地図のマスを取り合うブラウザゲーム（https://keigamesstudio.com/baka/jintori/ ）。
5. サーバーを軽くするため、1人がサーバーに送るのは「このマスを取る」などの数回だけにする。何万人来ても、安い費用で動かせる。

## 3. 遊びの流れ

### 3.1 毎日の流れ
1. アプリを開くと、自分の工場（自分の端末の中で動く。今の Ironfield と同じ）が出る。
2. 工場で鉄や銅から部品を作り、最後に「旗」を作る。
3. 地図の画面に切り替え、旗を使って自分の県の隣のマスを取るか、自分の県のマスを守る。
4. 毎日21時に、その日の勢力図が出る。X に貼れる画像も作る。

### 3.2 旗のしくみ
- 旗は工場の生産ラインの最後に作る特別な品物。作るには、鉄板・銅線・歯車などを組み合わせた部品がいる。
- **1日に使える旗は3本まで**（たたき台）。日本時間の朝5時に戻る。
- **使わなかった分は2日分まで持ち越せる**。1日休んでも、次の日に取り返せる（毎日来られない人にやさしく）。
- 旗を作れるのは1日の上限まで。上限を超えて作っても旗にはならないので、長時間の作業で旗をため込むことはできない。
- 研究を進めると、旗が少ない材料で作れるようになる。うまく工場を組んだ人は短い時間で上限に届く。上手な人は時間を節約できるという得をするが、取れるマスの数は同じ。

### 3.3 マスの取り方
- 地図は日本全体をマスに分けたもの。マスの大きさは要検討（4章）。
- 取れるのは、自分の県がすでに持っているマスの隣だけ。最初は各県の県庁所在地のマスから始まる。
- 旗1本で、だれのものでもないマスを1つ取れる。
- 他の県のマスを取るには、そのマスの「守り」の分だけ多く旗がいる。
- 自分の県のマスに旗を使うと、守りが1つ上がる（上限あり）。

### 3.4 人数の補正
- 県ごとに「その日に遊んだ人数」で旗の力を割り引く。人の多い東京や大阪で1人が立てた旗は、人の少ない県の旗より弱い。
- 計算のしかたは陣とりバトルを参考に、遊びながら調整する。

### 3.5 シーズン
- 1か月を1シーズンとする。月初めに地図をまっさらに戻す。
- 工場はシーズンをまたいで残す。ただし旗の上限があるので、長く遊んでいる人が陣取りで強くなりすぎることはない。
- シーズンの終わりに、県ごとの順位と、毎日続けた人の記録（何日続けたか）を残す。

## 4. 決めたこと

2026-10-23 にユーザーが「その案でいい」と決めた。下の表の「たたき台」の列が、決まった内容。ただし「個人の工場を他人に見せるか」は、まだ確かめていない。

| 項目 | 候補 | たたき台 |

## 5. しくみ（技術）

### 5.1 全体の形
- **工場**: 各自の端末の中だけで動く（今の Ironfield の計算をそのまま使う）。サーバーとは通信しない。
- **地図と陣取り**: Cloudflare（Workers と Durable Objects）に、おおもとのデータを置く。サーバーは「旗を使ってよいか」を確かめて記録し、地図を配るだけ。
- **画面の配信**: 今と同じ GitHub Pages。

### 5.2 サーバーとのやりとり
| やること | 回数の目安 |
|---|---|
| 地図をもらう（最初は全体、あとは変わった所だけ） | 開いたとき1回＋30〜60秒ごと |
| 旗を使う（マスを取る・守る） | 1人1日3回まで |
| 今日の旗の数を報告する（工場で作った分） | 旗を作ったとき。1日数回 |

1人1日あたり、書き込みは10回以内。陣とりバトルと同じくらいの軽さ。

### 5.3 料金の見積もり（推測）
- Cloudflare の無料枠は1日10万回の受け付けと、1日10万行の書き込み。
- 1人1日10回の書き込みなら、1日に約1万人までは無料枠に収まる見込み。超えたら月5ドルの有料プランに切り替える。
- 地図は変わった所だけ送り、全体の地図は数分おきに作って、配信の網（CDN）に任せる。

### 5.4 ずるの防ぎ方
- 工場は端末の中なので、「旗を作った」という報告をごまかすことはできてしまう。
- ただし1日の上限があるので、ごまかしても、毎日まじめに上限まで作る人と同じだけしか取れない。上限がずるの効き目を小さくしてくれる。
- 残る問題は「1人で何台も使う」こと。陣とりバトルと同じく、端末の特徴と回数の制限で見張る。アカウント登録は求めない。
- 「ありえない速さで旗を作った」報告は、サーバーで弾く（研究の進み具合から作れる速さの上限を出す）。

## 6. 作る順番

1. 旗（品物とレシピ）と、1日の上限・持ち越しを工場に足す。ひとりで遊べる形で確かめる。
2. 地図の画面（日本地図とマス、県の色分け、自分の県の選択）。最初は手元だけで動く見本。
3. Cloudflare のサーバー（地図のおおもとのデータ、旗の受け付け、1日の上限、人数の補正、シーズン）。ユーザーの Cloudflare アカウントが必要。
4. 21時の勢力図と、X に貼れる画像。
5. ずる対策と、大人数の試験（仮の参加者を何千人分も動かす）。
6. 公開。

## 7. 必要なもの
- ユーザーの Cloudflare アカウント（無料。登録とログインの許可はユーザーが行う）。
- 日本地図の形のデータ。国土数値情報などの自由に使えるデータから作る（使ってよい条件を確かめてから）。

## 8. 進み具合

### 2026-10-23（Ironfield #3）

作る順番の1と2ができた。

- 工場に「旗」を足した。最初の旗は持ち物から手で作れる（歯車5・銅線10・電子回路3・レンガ4、10秒）。研究「旗の改良」（赤のパック40個）をすると、組立機で安く作れる（歯車2・電子回路2・レンガ2、5秒）。
- 地図の画面を足した。工場の画面の右上にある「陣取り」ボタンで開く。日本を10km四方の4,223マスに分けた（形は Natural Earth という、自由に使ってよい地図データから作った）。
- 1日に使える旗は3本。日本時間の朝5時に3本ふえ、使わなかった分は最大9本（2日分の持ち越し）までたまる。
- マスは自分の県のマスのとなりだけ取れる。だれのものでもないマスは旗1本で取れる。ほかの県のマスは、旗1本ごとに守りが1つ下がり、守りが0のときに旗を使うと奪える。自分のマスに旗を使うと守りが1上がる（最大5）。いちばん近い島どうしは「海の渡り」でつないだ。
- 県庁のマスは取られない（最初の拠点がなくならないように。設計書には無かったので足した）。
- 自分の県はシーズン中に旗を1本も使っていなければ変えられる。月が変わると地図は最初に戻り、県も選び直す。
- サーバーはまだ無いので、ほかの県の動きはコンピューターがまねしている（各県が1日3本ずつ、県庁に近いマスから広げる）。記録はこの端末の中だけに残る。

### まだ決めていないこと

- いまは、作った旗を持ち物に何本でもためておける（1日に使える本数は3本まで）。そのため、一度に大量に作っておけば、あとは毎日ひらいて使うだけで済んでしまう。設計書の「上限を超えて作っても旗にはならない」に近づけるなら、「持てる旗の数に上限をつける」か「旗は作った日の翌朝5時に消える」などの決まりが要る。どちらにするかはユーザーが決める。

### 次にやること

- 3. サーバー（Cloudflare）。ユーザーの Cloudflare アカウントが必要。地図の記録の置き場所は `src/jintori/store.js` の1か所にまとめてあるので、そこをサーバー版に入れかえる。人数の補正もサーバーで計算する。

### しくみのメモ

作業する人に向けたメモ。

- 地図のマス: `src/jintori/japan.js` は `tools/build-japan-grid.mjs` で作る。元のデータは Natural Earth 1:10m admin-1（パブリックドメイン）の日本の47都道府県
- 画面: `src/jintori/view.js`。工場とのつなぎはシミュレーションの命令 `useFlag`（持ち物から旗を1本減らし、`flag-used` を知らせる）だけ

## 9. 次の方針

2026-10-23 の夜、ユーザーから次の指示があった。「都道府県ごとでみんなが構築できる場所にしよう。鯖は全鯖共通でいこう。自己鯖は開かないようにしましょう。あとクオリティをもっと上げてほしい。制作に使えるものあればいくらでも使ってよい」

Claude が「県ごとに別のワールドを47個作る」と「1つの大きなワールドを47の区画に分ける」の2つの読み方を示し、ユーザーは後者を選んだ（同じ夜）。

### 決まったこと

- 工場のワールドは全員で1つ。その中を47の区画に分け、プレイヤーは自分の県の区画に工場を作る。
- 日本地図（陣取り）も全員で1つを共有する。そのためにサーバー（Cloudflare）が要る。ユーザーの Cloudflare アカウント（無料）が必要。
- 自分でワールドを公開する機能、部屋番号での参加、公開中のワールドの一覧はなくす。

### まだ決めていないこと

- 「ひとりで遊ぶ」と、いまの「みんなのワールド」を残すか。Claude のおすすめは、どちらも大きなワールドに置きかえてなくすこと（ほかの場所で旗を作る抜け道をなくすため）。→ #4 でおすすめどおりなくした（仮）。
- 区画の形。日本地図の形にそって県を並べるか、同じ大きさの区画を並べるか。→ #4 で「同じ大きさの区画を日本地図の形に並べる」にした（仮）。
- 区画の境をまたいでベルトなどを置けるか。→ #4 で「置けない」にした（仮）。

### 気をつけること

- いまの共有ワールドは、中にいる人のブラウザが計算役になり、公開の MQTT サーバーで操作を配っている。この形のまま全員を1つのワールドに入れると、人数が増えたときに重くなったりずれたりする。
- Claude の案: 見た目は1つのワールドにし、計算は区画ごとに分ける。各区画は、いまの「みんなのワールド」と同じしくみ（区画ごとに部屋を1つ）で動かし、となりの区画は保存された写しを見せる。区画の境をまたぐ建物を置けなくすれば、区画どうしは別々に計算できる。人が増えたら、区画ごとの計算をサーバー側へ移す。

### 2026-10-23（Ironfield #4）作り直しの1歩目

「1つの大きなワールドを47の区画に分ける」の土台ができた。決まっていなかった3つは、Claude のおすすめで仮に決めて作った（あとで変えられる）。

- 「ひとりで遊ぶ」「自分のワールドを公開する」「部屋番号で参加」「公開中のワールドの一覧」「保存したワールド」「みんなのワールド」をタイトル画面からなくした。旗を作れるのは県の区画だけになる。前の「みんなのワールド」（部屋 PLAZA2）の中身は、通信サーバーとこの端末に残っているが、もう入り口はない。
- 区画の形: 同じ大きさの四角を、日本地図の形にならべた（14列×11行。北海道が右上、沖縄が左下）。1つの区画は今までの1ワールドと同じ 512×512 マス。県ごとに地形の元になる数（シード）を変えたので、どの県も景色がちがう。
- 区画の境をまたぐ建物: 置けない。いまは区画ごとに別々の計算なので、そもそも境の外には置けない。
- タイトル画面: 名前と色の下に、47区画の日本地図を出す。県をえらんで「○○の区画に入る」を押す。いま作業している人がいる区画には緑の点が出る。
- 県と区画は同じもの: タイトル画面でえらんだ県が、陣取りの「自分の県」になる。陣取りの画面で県を変えると、工場もその県の区画へ移る。シーズン中に旗を使ったあとは、どちらでも県を変えられない（今までと同じ決まり）。
- しくみ: 区画ごとに部屋を1つ使う（`plotRoom(県番号)`、例 東京＝KENZAP）。だれもいない区画に入った人が計算役になり、抜けたら残った人が引き継ぐ。前の「みんなのワールド」と同じしくみを47個に広げた形。区画の並びは `src/plots.js`。
- 確かめたこと: 2つのタブで同じ東京の区画に入れた（2人）。陣取りの画面で大阪に変えると工場も大阪の区画へ移った。スマホの幅でも県名が切れない。`node tools/simtest.mjs` と `node tools/jintori-test.mjs` は合格。

### 2026-10-23（Ironfield #4）見た目を1つのワールドに

- 地形を日本全体で1つにした。区画ごとに外側が海に落ちるのをやめ、大きなワールドの位置で地形を決めるので、となりの区画と境でつながる（東京と千葉の境の512マスで一致を確かめた）。となりに県がない側（タイルの地図で空いている所）だけが海岸になる。鉱石と油、スタート地点のまわりと池だけは区画ごと。
- 区画の外の64マスに、となりの区画の地形と木を、少し暗くして描く。区画の境には明るい線を引き、境のすぐ外に「○○県の区画」と名前を出す。カメラは境を16マス越えて見に行ける。建物は置けない。
- いまはとなりの区画の「生まれたときの地形」を見せているだけで、そこで建った建物や掘られた鉱石は映らない。
- 地形の作り方が変わったので、区画の部屋を新しくした（KENZ… → KENY…、端末の写しも plot- → plot2-）。前の作り方の東京・大阪の区画は、確認用に開いただけなので捨てた。
